# Bio-Analysis 实验脉络（给人看的版本）

这份文档回答四个问题：我们在研究什么、数据长什么样、每一步实验做了什么又得到了什么、现在的结论是什么。每一节都先给一句话结论，再给例子。技术细节和全部数字在 `doc/context_claude.md`，代码入口在 `README.md`。

---

## 1. 问题

小鼠听到提示音（出水口过来）后伸爪去够水。双光子记录运动皮层几十个细胞的钙信号。我们想知道：

1. **哪些细胞跟"够水"这个动作锁在一起**，能不能用它们预测动作，而且不作弊。
2. **成功够到水的细胞，和没够到的（missed）、够空的（in vain）、只有提示音没动作的，是不是同一批细胞**。换句话说，这批细胞编码的是"伸爪子"还是"喝到水"。

---

## 2. 数据

| 东西 | 内容 |
|---|---|
| 一个 token（如 `K227_A_D7`） | 一只小鼠、一个视野、一天的一次记录，约 20 分钟 |
| `_S.csv` | 每个细胞每秒一个数（去卷积后的尖峰，六成是 0），约 1200 行 |
| `_B.csv` | 行为标注：名字 + 起止帧（7.06 帧/秒）。成功够水 `cont reach`，够空 `cont in vain`，没够到 `cont missed`，走路 `walk`，提示 `valve opened` |
| 规模 | initialization 30 个 token，memory 16 个 token，合计 45 个有成功事件的 token |

**一个试次长什么样**：提示音响 → 0.6 秒后小鼠第一次伸爪（成功或 missed）→ 喝水 → 之后几秒内常常再伸几次爪子但水已经没了（in vain，中位数在提示后 3 秒）。所以"成功"和"missed"处在试次的同一个阶段，"in vain"处在另一个阶段，而且前面刚喝过水。这个结构后面会反复用到。

---

## 3. 第一步：发现旧方法作弊了

**结论**：旧代码报告的 0.9 准确率是数据泄露，随机游走的假细胞也能得 0.9。

**为什么**：信号每秒一个点，被插值成每 0.1 秒一个点，相邻 10 帧几乎一模一样。旧代码把帧随机打乱再分训练/测试，于是每个测试帧在训练集里都有一个"双胞胎"，模型背答案就行。

**例子**：把全部细胞换成随机游走（和标签毫无关系），同样的流程还是 0.90。换成按时间切块的评估，真细胞 0.54，假细胞 0.515。

**做了什么**：删掉旧的筛选和预测代码（sps_select、rfecv）及其缓存，所有评估改成"时间分块"：

- 记录切成 5 段连续的时间块，轮流当测试块；
- 测试块两侧各扔掉 5 秒，防止插值把信息漏过去；
- 归一化、细胞排序全都只用训练块的数据；
- 报告"块内 AUC"（每个测试块单独算 AUC 再平均），因为事件在时间上扎堆，合并算会被跨块的基线差异拖垮；
- 永远带一个随机游走对照。

---

## 4. 第二步：找一个不靠模型的"清晰度"

**结论**：一个细胞"清不清晰"可以只用信号算出来，而且它能预测这个 token 的模型表现（Spearman 0.79）。

**定义，用例子说**：把一个细胞在每次成功够水前后 ±5 秒的信号截下来，一次事件一行，叠成一张图（就是 heatmap）。如果这个细胞真的跟动作锁在一起，每一行的样子应该差不多，于是行与行的相关系数高；这个"行与行平均相关"叫 **coherence**。

但相关高也可能是巧合，所以做一个这段记录自己的对照：把标签在时间上整体转一圈（事件时刻全部平移一个随机量），重新算 coherence，重复 1000 次，得到"瞎对齐能有多高"的分布。真实值离这个分布有多少个标准差就是 **z**。z ≥ 2 的细胞叫**显著清晰**。一个 token 的清晰度 = 显著细胞的比例。

**结果**（`plot/clarity/auc/cont/`）：45 个 token，清晰度和 ExtraTrees 的块内 AUC 的 Spearman 是 0.785；init 0.78，memory 0.76（memory 是选定指标之后才看的，相当于留出集）。只看清晰度就能以 0.93 的 AUC 判断哪些 token 能达到 0.75。随机游走对照 AUC 0.52。

**这个结论的分量**：它当然有点"废话"（看得见纹理的当然好学），但它把这个直觉变成了一个不用训练、带对照、能迁移到留出集的数字，告诉你哪些记录值得建模。

---

## 5. 第三步：清晰的细胞是不是真的扛信息

**结论**：最清晰的 30% 细胞比最不清晰的 30% 高 0.10 AUC（45 个 token 里 37 个赢，p < 1e-6），比同样数量的随机细胞高 0.024，和用全部细胞比只差 0.014。

**怎么做的**：每一折只用训练块给细胞按 z 排序，取前 30%、后 30%、随机 30%、全部四组分别训练 ExtraTrees，比块内 AUC。排序永远看不到测试块。

**怎么说才准确**：清晰细胞扛信息，这句成立；"只有清晰细胞扛信息"不成立，因为在清晰的 token 里信息在很多细胞上是冗余的，随机抓 30% 也能抓到一些。

| | 全部 | 最清晰 30% | 随机 30% | 最不清晰 30% |
|---|---|---|---|---|
| 45 个 token 平均块内 AUC | 0.715 | 0.701 | 0.677 | 0.602 |

**模型搜索**：试过 LightGBM、CNN、GRU、LSTM、Transformer、ROCKET、集成、focal loss、负采样、各种插值和滤波。ExtraTrees 最好（0.730 对 LightGBM 0.676，29 个 token 里 28 个赢），没有任何模型能把清晰/不清晰 token 的差距拉大：强模型把不清晰的也一起抬高了。差距是数据的属性，不是模型的。

## 6. 第四步：合作者的方法

**结论**：她的事件级解码器没有标签泄露，但"成功 vs in vain"这个对比混进了试次阶段，所以它的高 AUC 回答不了"是不是同一批细胞"。

**她做了什么**：每个标注当一个事件，取事件前 2 秒到后 4 秒的窗口，成功够水是正类，其他全是负类，LightGBM 嵌套交叉验证，AUC 0.89。

**问题在哪，用例子说**：成功够水的窗口里，前 2 秒有刚响过的提示音、之前是安静等待；in vain 的窗口里，前 2 秒是上一次成功够水和喝水的尾巴、没有提示音。模型不用看"这次够水"本身，看"前面有没有提示音 / 是不是刚喝完"就能分开。证据：只用事件**之前**的 3 到 1 秒也有 0.855。

**对我们的意义**：真正阶段匹配的对比是**成功 vs missed**，两者都是提示后的第一次伸爪，唯一区别是有没有喝到水。她选出来的细胞和我们的显著清晰细胞高度重合（K227_A_D7：24 个里 22 个），所以两套方法看的是同一批细胞。

## 7. 第五步：成功 / missed / in vain / 提示 的两两对比

这是回答"伸爪子还是喝到水"的核心实验。脚本 `script/clarity_contrast.py`，图在 `plot/clarity/contrast/cont/`。

### 7.1 三种测量

1. **细胞重合率**：分别以成功、missed、in vain、只有提示、走路为目标算清晰度，各自得到一组显著细胞；看另一组里有多大比例落在成功细胞里（共享 / 较小的那组），并和"随机抽两组同样大小"的机会水平比。
2. **响应形状相似度**：每个细胞在某类事件上的响应 = 事件后 0 到 1 秒的均值减事件前 2 到 1 秒的均值，在所有事件上平均。两类事件各得一条"每个细胞的响应"，跨细胞算相关系数 r。对照是把两类事件的标签随机打乱重贴（同一类事件分成两半能有多像），r 落在对照里就是"分不出来"，明显低于对照就是"真的不一样"。
3. **群体时间曲线**：成功细胞在每类事件前后每秒的平均活动。

### 7.2 结果

| 对比（参照：成功细胞） | 重合率 观测 / 机会（token 数） | 响应相关 r 观测 / 对照（token 数） | z | 解读 |
|---|---|---|---|---|
| 成功 vs missed | 0.67 / 0.62（9） | 0.44 / 0.38（14） | +0.4 | 同一批细胞，响应一样 |
| 成功 vs in vain | 0.59 / 0.48（30，p 0.001） | −0.01 / 0.34（40） | −2.5 | 清晰 token 里同一批细胞，响应相反 |
| 成功 vs in vain（刚喝完 3 秒内） | 0.59 / 0.47（30） | 0.01 / 0.36（39） | −2.6 | 同上 |
| 成功 vs in vain（孤立，前 8 秒无成功） | 0.62 / 0.54（7） | −0.06 / 0.31（20） | −2.3 | 同上，兴奋更强 |
| 成功 vs 只有提示 | 0.46 / 0.41（21，机会水平） | −0.01 / 0.30（40） | −3.6 | 另一群细胞，成功细胞不响应 |
| 成功 vs 走路 | 0.57 / 0.51（35） | −0.07 / 0.25（39） | −2.5 | 响应不同 |

重合率合在一起看分辨力不高：有足够细胞做比较的 token 里成功细胞本来就占一半，机会水平也有 0.4 到 0.6，最清晰的 token 里机会水平接近 0.9。所以重合率图按 token 的清晰度分成 15 个等宽桶（成功显著细胞比例，≥ 0.4 算清晰，深色），每个对比一张直方图，再叠一条核平滑的观测趋势线（实线）和机会趋势线（虚线），结论看清晰一侧（下表把桶合并成清晰 / 不清晰两侧）：

| 对比 | 清晰 token 数 | 清晰一侧重合率（机会） | 清晰一侧按细胞合计 | 不清晰一侧重合率（机会） |
|---|---|---|---|---|
| missed | 8 | 0.75（0.66） | 74 / 84 | 只有 1 个 token |
| in vain | 15 | 0.72（0.64）；0.6-0.8 桶 0.87（0.71） | 227 / 269 | 0.46（0.32） |
| in vain（刚喝完） | 14 | 0.81（0.64），p 0.003 | 248 / 280 | 0.40（0.32） |
| 只有提示 | 8 | 0.69（0.65），每个桶都在机会上下 | 27 / 40 | 0.32（0.26） |
| 走路 | 17 | 0.68（0.64），0.6-0.8 桶 0.73（0.73） | 165 / 233 | 0.46（0.39） |

读法：清晰 token 里 in vain 的细胞就是成功细胞（高出机会 0.15 到 0.2），missed 的细胞也是（按细胞 74/84，但只有 8 个 token），提示的细胞不是（每个桶都在机会水平或以下），走路在机会水平。不清晰 token 里两边的集合都很小，所有对比都在机会附近。"响应一不一样"仍然看响应相关 r：成功 vs missed 落在对照里面，其他所有对比都在对照下方 2 到 3.6 个标准差。

逐条解读：

- **成功 vs missed**：同一批细胞，响应一样。r 在对照范围内（z +0.4），事件前、事件时、事件后 3 到 5 秒三段都测不出差别。这组对比里提示音两边都有、余波两边都没有，是最干净的一组。
- **成功 vs in vain**：很大程度上是同一批细胞（强 token 里重合 0.7 到 0.9），但响应方向相反：成功时细胞在动作前后被**抑制**，in vain 时动作后 1 到 3 秒**兴奋**。跨细胞 r ≈ 0，比对照低得多（z −2.5）。之前把"r ≈ 0"误读成"两批不同的细胞"，后来直接以 in vain 为目标算清晰度才发现重合很高，正确的说法是"同一批细胞、相反的形状"。
- **孤立的 in vain**（前 8 秒没有任何成功够水）：兴奋更强，所以这个兴奋不是上一次动作的余波。
- **成功 vs 只有提示**：提示音有自己的一小群细胞（约 10% 的细胞），和成功细胞的重合在机会水平；成功细胞在没有伸爪的提示上不响应（z −3.6）。提示音不直接驱动这批细胞。
- **成功 vs 走路**：不同的响应（z −2.5）。

### 7.3 两个干扰项怎么处理的

| 对比 | 提示音 | 上一次动作/喝水的余波 |
|---|---|---|
| 成功 vs missed | 两边都有，抵消 | 两边都没有，抵消（事件前窗口差异 z −0.08） |
| 成功 vs in vain | 成功有、in vain 没有 | 成功没有、in vain 有 |

对第二组：提示音被"只有提示"实验排除（成功细胞不响应提示本身）；余波被"孤立 in vain"实验排除（没有余波时兴奋更强）。

### 7.4 结论

- **不是因为喝到水**：missed 没喝到水，细胞和成功一模一样。
- **也不只是因为伸爪子**：in vain 也伸了爪子，同样的细胞响应却反过来。
- **也不是提示音刺激本身**：提示音有另一群细胞。
- **最接近的说法**：这批细胞编码的是"在有水可拿的情境下的那一次伸爪"。提示刚响、第一次去够时被抑制；水没了、再去够时兴奋。

**还没分开的**：in vain 时方向反转的原因有三个候选，现有数据分不开：没有提示音情境、这个试次已经喝过水的状态、动作本身不同（第一次是瞄准的，后面是随意的）。能分开它们的事件是"提示音响了、还没喝到水、就先够空了一次"，数量少但数据里有；加一个 target 就能跑。

## 8. 仓库怎么用

```
src/preprocess   帧级对齐（Preprocessor）、时间分块 + 随机游走对照（BlockPreprocessor）、原生采样率事件窗口（EventPreprocessor）、目标注册表 TARGETS
src/clarity      ClarityEngine（清晰度）、ContrastEngine（两两对比）、ClarityVisualizer（heatmap / curve / 重合率 / 响应曲线）
src/prediction   ExtraTreesEngine（无泄露预测）、PredictionSummarizer（排名图 / 子集图）
src/deduction    原有的尖峰窗口扩展分析
src/util         logger、文件夹装饰器、load_paths、并行 map
script/          clarity_map / clarity_auc / clarity_subset / clarity_contrast / deduce_3d / deduce_viz
cache/           每个引擎的输出，配置相同就直接复用
plot/            全部 svg
```

跑一遍完整流程（在 `script/` 下，`PYTHONPATH=..`，conda 环境 `regular`）：

```bash
python clarity_map.py      --beh cont --view-width -80 80      # 每个 token 的 heatmap / curve，显著细胞排前面，灰色蒙版是清晰度没看的区域
python clarity_auc.py      --beh cont --noise                  # 清晰度 vs AUC 排名图 + 随机游走对照
python clarity_subset.py   --beh cont                          # 最清晰 / 随机 / 最不清晰 / 全部
python clarity_contrast.py --first cont                        # 成功 vs missed / in vain / 提示 / 走路
```

想加一种事件：在 `src/preprocess/target.py` 的 `TARGETS` 里加一个条目，所有脚本的 `--beh` / `--seconds` 立刻可用。

**读图小抄**

- heatmap：一个格子一个细胞，暖色是显著清晰的细胞（按 z 从高到低），冷色是其他细胞；一行一次事件，横轴是事件前后的帧（0.1 秒）；灰色蒙版盖住的是清晰度计算没用到的帧。
- curve：同一布局，把事件平均成一条线。
- 排名图：上面是每个 token 的块内 AUC（深色；灰色是随机游走对照），下面是同一顺序的清晰度比例（浅色）。
- 子集图：四种细胞子集在 init / memory / 合并上的平均 AUC。
- 重合率图：每对事件类型一张直方图，x 轴是 token 的清晰度（15 个桶），柱高是"共享细胞 / 较小组"的平均，柱顶数字是 token 数，深色桶是清晰 token，浅色桶是不清晰 token，实线是核平滑的观测趋势，虚线是机会趋势。
- 响应图：左边是跨细胞响应相关 r 和它的重贴标签对照，右边是成功细胞在每类事件前后的群体曲线。
